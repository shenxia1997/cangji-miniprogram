### 2.4 单位与运算（`domain/money.ts`）

| 量 | 单位 | 换算 | 示例 |
| --- | --- | --- | --- |
| 价格 | 厘 | 元 × 1000 | 51.80 元 = 51,800 |
| 数量 | 千分之一股 | 股 × 1000 | 200 股 = 200,000 |
| 金额 / 成本 / 盈亏 | 分 | 元 × 100 | 1,036.00 元 = 103,600 |

**核心换算（必须作为函数实现并测试）**

```ts
// 成交额（分）= round(price(厘) * quantity(千分之一股) / 10000)
export const mulPriceQty = (priceLi: number, qtyMilli: number): number =>
  Math.round((priceLi * qtyMilli) / 10000);

// 元字符串 → 分。'51.80' → 5180
export function yuanToCents(input: string | number): number;

// 分 → 展示字符串，带千分位。1036500 → '10,365.00'
export function centsToYuan(cents: number, withGrouping = true): string;

// 分 → 单价展示（厘）。1036500 / 200000 → 51800
export function unitPriceLi(remainCost: number, remainQtyMilli: number): number;
```

**除法规则（全项目唯一除法点）**

```
除以「数」一律 Math.round；余数用减法反求，禁止二次除法。
结转成本 = Math.round(成本总额 * 卖出量 / 总量)
剩余成本 = 成本总额 - 结转成本        ← 必须用减法，保证两者之和恒等于原值
```

### 2.5 计算口径

#### 2.5.1 加权平均（`pnl.ts`）

```
结转成本 = Math.round(持仓成本总额 * 卖出量 / 当前总份额)
已实现盈亏 = 卖出成交额 - 结转成本 - 卖出费用
持仓成本总额 -= 结转成本
持仓份额     -= 卖出量
```

#### 2.5.2 指定批次（`allocations.ts`）

```
对每个 allocation：
  结转项 = Math.round(该批次 remainCost * 分配量 / 该批次 remainQuantity)
  批次 remainCost     -= 结转项
  批次 remainQuantity -= 分配量
  批次 realizedPnl    += 该批次分摊的盈亏（见下）
结转成本合计 = Σ 结转项
已实现盈亏 = 卖出成交额 - 结转成本合计 - 卖出费用
```

**成本基数已含买入费用**，因此公式只有三项。禁止再减一次买入费用（会重复扣费）。

#### 2.5.3 派生与聚合

```
批次状态：remainQuantity === 0 → 'closed'
          remainQuantity === quantity → 'holding'
          其余 → 'partial'

持仓：按 instrumentId 聚合 remainQuantity 与 remainCost
市值 = Math.round(lastPrice * quantity / 10000)
浮动盈亏 = 市值 - costTotal
```

### 2.6 两条结构性要求

| # | 要求 | 理由 |
| --- | --- | --- |
| S1 | `lotId` 必须等于买入交易的 `uuid` | 删除中间一笔买入后，历史卖出的 `allocations.lotId` 仍然有效；用顺序号会整体错位 |
| S2 | 不建 `lots` 集合，批次只在快照中缓存 | 批次完全由买入交易派生，落库会产生两份真相 |

### 2.7 重放主流程（`replay.ts`）

```
输入：Transaction[]（含已删除，自行过滤）+ config
输出：ReplayResult

1. 过滤 deletedAt !== 0
2. 排序：tradedAt 升序，相等时 createdAt 升序（保证确定性）
3. 逐笔：
   buy  → 建 Lot（lotId = uuid，costTotal = amount + feeTotal）
   sell → 若 method === 'specified' 且有 allocations：走 2.5.2
          否则：走 2.5.1（auto_fifo 时按 openedAt 升序逐批扣减，每批内部仍用 2.5.2 的比例结转）
4. 异常：剩余量将变负 / 分配合计 ≠ 卖出量 → 记录 Anomaly，跳过该笔盈亏累加，继续
5. 聚合持仓 → 计算市值与浮动盈亏
```

### 2.8 异常码（`domain/errors.ts`）

| code | 触发 | 界面表现 |
| --- | --- | --- |
| `E_OVERSELL` | 卖出量 > 可用份额 | 该笔标灰 + "数据异常，点击修复" |
| `E_ALLOC_MISMATCH` | 分配合计 ≠ 卖出量 | 同上 |
| `E_ALLOC_EXCEED` | 单批分配 > 批次剩余 | 同上 |
| `E_NEGATIVE_COST` | 成本算成负数 | 同上 |
| `E_ZERO_QTY` | 数量为 0 | 录入时即拦截，不进库 |
