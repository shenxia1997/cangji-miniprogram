# 仓记 · 基金股票交易记账小程序

微信小程序，用来记录基金与股票的每一笔买卖，并把"卖出的是哪一批"算清楚 —— 做 T 时按指定批次结转成本，而不是笼统的全仓均价。

## 快速开始

```bash
npm install

npm run check        # 类型检查 + 全部测试
npm run test:golden  # 金标准 4 组（数字必须逐分命中）
npm run test:prop    # 6 条不变量的属性测试
npm run bench        # 3000 笔交易重放计时
```

用微信开发者工具导入本目录即可运行（`project.config.json` 已配置 TypeScript 编译插件）。正式使用前把 `appid` 换成自己的小程序 AppID。

## 三个不能改的设计约定

**1. 金额全部用整数。** 价格用「厘」，数量用「千分之一股」，金额用「分」。任何 `price * quantity` 的浮点乘法都是缺陷。

**2. 批次 ID 就是买入交易的 UUID。** 不用顺序号 —— 用户删掉中间一笔买入后，顺序号会整体前移，历史卖出记录里的"批次 2"就指向了原本的批次 3，盈亏会算错且极难察觉。

**3. 不存加权单价，只存成本总额。** 单价除不尽时是无限小数，后续用"单价 × 数量"反算总额必然累积误差。除法只出现在卖出结转一处：

```
结转成本 = round(成本总额 × 卖出份额 ÷ 总份额)
剩余成本 = 成本总额 − 结转成本      ← 用减法，保证两者之和恒等
```

## 可验证的正确性

`tests/fixtures/golden.ts` 是全项目唯一的期望值来源。三笔买入（200@51.80 / 500@48.20 / 300@46.90，各费 5 元）后总成本 4,854,500 分，然后：

| 情形 | 结转成本 | 已实现盈亏 | 剩余均价 |
| --- | --- | --- | --- |
| 加权卖出 300 股 @52.00 | 1,456,350 | 100,590 | 48.545 |
| 指定批次（B3:200 + B2:100） | 1,420,433 | 136,507 | 49.058 |
| 拆分卖出 500 股 @50.00 | 2,371,700 | 125,300 | 49.656 |

指定批次卖掉了低成本批次，剩余均价从 48.545 升到 49.058 —— 这不是 bug，是"好货先出手"的必然结果，产品上用回执提示和口径说明页解释。
